# TechCast

IT・SaaS・AI業界のニュースを毎朝自動で集めて、**耳で聞ける番組**にする個人用アプリ。

業界未経験からの転職に向けたインプットを想定している。
ニュースを読み上げるだけでなく、その日に出てきた業界用語の解説と、
面談や面接での使いどころまでを 1 本の番組に入れている。

聞き方は 2 通りある。

1. **このアプリで聞く** — 設定不要。開くだけでその日の番組ができて、ブラウザが読み上げる
2. **普段のポッドキャストアプリで聞く** — 音声合成を設定すると MP3/WAV が作られ、
   Apple Podcasts や Spotify、Pocket Casts に自分専用の番組として登録できる

設計の理由と展望は [DESIGN.md](./DESIGN.md) に書いてある。

---

## できること

**集める**

- 27 媒体（日本語 17／英語 10）から毎朝フィードを取得する。AI の一次情報を含む
- **URL が死んでいても自力で復帰する**。代替の場所を順に試し、それでもだめなら
  サイト本体を見てフィードの移転先を探す。最後は画面から手で直せる
- 同じニュースの重複をまとめ、複数媒体が報じた記事を重要とみなす

**選ぶ**

- 「AI中心」「SaaS・事業中心」「バランス」のプリセットで、情報源と興味の重みをまとめて切り替える
- 16 トピックごとに重みを調整して、選ばれる記事を志望領域に寄せる
- 過去に扱った記事は翌朝の候補から外す

**届ける**

- 5 分／10 分／15 分の番組として台本にする
- ブラウザの音声合成で再生。コーナー単位で頭出しできる
- **ロック画面とイヤホンのボタンから操作できる**。再生中に画面を消さない設定もある
- **ホーム画面に追加できる**（PWA）。圏外でも過去の番組を開ける
- その日の記事に出てきた業界用語を解説する。覚えた語は次から出ない
- 日付が変わってアプリに戻ると、その日の番組を自動で作り直す

## 動かす

**アプリ内で聞くだけなら、これだけ。**

```bash
cd techcast
npm install
npm run dev
```

http://localhost:5174 を開く。初回は自動でその日の番組を作り始める。

**音声ファイルを作って毎朝自動更新するなら**、常駐させる。

```bash
npm run build
npm start          # http://localhost:3000
```

`npm start` のほうはスケジューラを内蔵していて、毎朝決まった時刻に番組を作り直す。

**最初にやること**：「情報源」タブの「使用中の情報源を確認」を押す。
読み込めないフィードがあれば、その場で移転先を見つけて「この URL に切り替える」で直せる。

### Claude に台本を書かせる（任意）

APIキーがなくてもテンプレートで番組は作られる。
キーを設定すると、次の 3 つが変わる。

- 英語記事が日本語に直される（未設定だと英語の見出しがそのまま読まれる）
- ニュース同士のつながりが説明される
- 用語解説がその日の文脈に合わせて言い直される

```bash
echo 'ANTHROPIC_API_KEY=sk-ant-...' > .env
npm run dev
```

### テストと静的検査

```bash
npm test     # 82 ケース。ローカルにサーバーを立てて、取得から配信まで通しで検証する
npm run lint
npm run build
```

## ポッドキャストアプリで聞く

ブラウザの読み上げには弱点がある。**画面を消すと止まる端末がある**ことと、
オフラインで音声を持ち歩けないことだ。普段のポッドキャストアプリで聞けるようにすると、
ロック画面・バックグラウンド再生・オフライン・再生位置の記憶が全部そちらの機能で手に入る。

**VOICEVOX を使って毎朝決まった時刻に用意する手順は、[docs/VOICEVOX.md](./docs/VOICEVOX.md) に
一本道でまとめてある。** 以下はその要約。

### いちばん短い道

```bash
cd techcast
cp .env.example .env          # ANTHROPIC_API_KEY を入れる（任意）
docker compose up -d          # VOICEVOX ごと起動する
```

これだけで、毎朝 4:30（日本時間）に番組ができ続ける。
`http://localhost:3000/api/podcast` をポッドキャストアプリに登録すれば購読できる。

必要なのは 3 つ。

### 1. 音声合成を設定する

どちらか片方でいい。

**VOICEVOX（鍵不要・無料・日本語の品質が高い）**

自分で engine を立てて、その URL を渡す。

```bash
# 例：Docker で動かす
docker run -d -p 50021:50021 voicevox/voicevox_engine:cpu-latest

echo 'VOICEVOX_URL=http://localhost:50021' >> .env
echo 'VOICEVOX_SPEAKER=3' >> .env   # 話者ID。好みで変える
```

**Google Cloud Text-to-Speech（立ち上げ不要・従量課金）**

```bash
echo 'GOOGLE_TTS_API_KEY=...' >> .env
echo 'GOOGLE_TTS_VOICE=ja-JP-Neural2-B' >> .env
```

共通の任意設定：`TTS_SPEED=1.2`（読み上げ速度）、`EPISODE_MINUTES=10`（尺）。

### 2. 毎朝、番組を作らせる

`npm start`（または `docker compose up -d`）で動かすサーバーには**スケジューラが内蔵されている**。
cron を別に用意する必要はない。

```bash
DAILY_HOUR=4
DAILY_MINUTE=30          # 5時に聞き始められるよう、少し前に作る
DAILY_TIMEZONE=Asia/Tokyo
```

サーバーの時計が UTC でも、指定したタイムゾーンの時刻で走る。
予定時刻に機械が止まっていた場合は、次に起動した時点でその日の番組がまだ無ければ自動で作る。

手で作りたいときはこれ。

```bash
npm run daily:now              # すでにある日は何もしない
npm run daily:now -- --force   # 作り直す
```

外部の cron や Vercel Cron から叩くこともできる。その場合の入口は `/api/cron`。
Vercel にデプロイしている場合は `vercel.json` に設定済み（毎日 19:30 UTC ＝ 日本時間 4:30）。
公開環境では `CRON_SECRET` を必ず設定すること。未設定だと誰でも叩ける。

### 3. ポッドキャストアプリに登録する

設定タブに出ている URL をコピーして、アプリの「URL で追加」に貼る。

```
http://localhost:3000/api/podcast
```

同じ家の Wi-Fi にいるスマホから聞くなら、`PUBLIC_BASE_URL` にそのマシンの IP を書く。

Apple Podcasts、Pocket Casts、Overcast、AntennaPod などはこの方法で購読できる。
Spotify は公開番組の登録しか受け付けないので、個人用途では他のアプリが向いている。

### 保存先について

生成した音声と台本は `TECHCAST_DATA_DIR`（既定は `.techcast-data/`）に置かれる。

**Vercel のファイルシステムは使い捨てなので、そのままではポッドキャスト配信は成立しない。**
VOICEVOX も置けない。この用途では常駐環境にする。

- 自宅サーバー、ミニPC、Raspberry Pi、VPS で `docker compose up -d`
- 普段使いの PC でも動く。ただし朝に電源が入っていないと、その時刻には作られない
  （次に起動したときに自動で作り直す）
- どうしても Vercel で配信したい場合は `server/audio/store.js` を
  S3 や R2 向けに差し替える。読み書きする関数は 4 つだけ

アプリ内で聞くだけなら Vercel のままで問題ない。

## デプロイ（Vercel）

独立したアプリなので、**ルートディレクトリを `techcast` に指定した別プロジェクト**として作る。

1. Vercel で新規プロジェクトを作り、Root Directory に `techcast` を指定する
2. Framework Preset は Vite
3. 環境変数を設定する（すべて任意）

| 変数 | 用途 |
|---|---|
| `ANTHROPIC_API_KEY` | Claude に台本を書かせる |
| `VOICEVOX_URL` または `GOOGLE_TTS_API_KEY` | 音声ファイルを作る |
| `CRON_SECRET` | 日次生成エンドポイントを保護する |
| `PUBLIC_BASE_URL` | ポッドキャストRSSに書く絶対URL |
| `TECHCAST_DATA_DIR` | 音声と台本の保存先 |

`api/` のファイルがそのままサーバーレス関数になる。
ローカルの `npm run dev` でも同じハンドラが動くよう Vite に橋を架けてあるので、
「ローカルでは動くのに本番で動かない」というズレが起きにくい。

### 処理の流れ

```
情報源カタログ
   ↓ 並列取得。死んだURLは代替→自動検出→手動修正で復帰する
フィードのパース（RSS 2.0 / RDF / Atom）
   ↓ 重複排除（固有名詞 + 数字 + 文字n-gram の 3 手がかり）
   ↓ スコアリング（鮮度 × 信頼度 × 興味 × 他媒体での言及）
   ↓ 選定（深掘りは 1 媒体 1 本まで／既出は除外）
用語の抽出（覚えた語を除く）
   ↓
台本生成（Claude、失敗したらテンプレート）
   ↓
  ├─ ブラウザで読み上げ（設定不要）
  └─ 音声ファイル化 → 保存 → ポッドキャストRSS（音声合成の設定が必要）
```

## 情報源を足す・直す

`server/sources.js` に 1 件足すだけ。

```js
{
  id: 'example',
  name: '媒体名',
  url: 'https://example.com/feed',        // 第一候補
  altUrls: ['https://example.com/rss'],   // 死んでいたら順に試す
  homepage: 'https://example.com/',       // 全滅したらここからフィードを探す
  lang: 'ja',              // 'ja' | 'en'
  tier: 'core',            // 'core' = 既定でON / 'extra' = 設定から追加
  weight: 1.0,             // 1.0 が基準。高いほど選ばれやすい
  tags: ['ai', 'japan'],   // taxonomy.js のタグID
  note: 'アプリに表示される一言説明'
}
```

カタログの URL が古くなっても、アプリ側が代替と自動検出で追いつく。
それでも読めないときは「情報源」タブの「URL を直す」で手入力できる。
直した URL はこの端末に保存され、カタログより優先される。

## 今のところできないこと

- **ブラウザ読み上げは画面を消すと止まる端末がある**。「再生中は画面を消さない」設定で
  回避できるが、根本的に解くには音声ファイル化（上記）が要る
- **端末間の同期**。設定と履歴はブラウザの中だけ。設定タブから書き出し／読み込みで移す
- **記事本文の取得**。フィードに含まれる要約までしか読まない
- **英語の日本語化（テンプレート時）**。Claude 経路でのみ翻訳される

---

## 注意していること

- フィードから取った文章は**外部から来たデータ**として扱う。台本生成のとき、
  記事中に指示めいた文言があっても従わないよう明示している
- 手元にあるのは見出しと短い要約だけなので、それを超えた断定をしないよう
  システムプロンプトで縛っている
- 読み上げ原稿に URL や記号を混ぜない（テストで検証している）
- エピソードIDは日付形式だけを受け付ける。保存先のパスに外から手を入れられないようにしている
