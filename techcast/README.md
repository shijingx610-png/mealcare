# TechCast

IT・SaaS・インターネット業界のニュースを毎朝自動で集めて、
ポッドキャストのように**聞ける形**にする個人用アプリ。

業界未経験からの転職に向けたインプットを想定していて、
ニュースを読み上げるだけでなく、その日に出てきた業界用語の解説と、
面談や面接での使いどころまでを 1 本の番組に入れている。

設計の理由と今後の展望は [DESIGN.md](./DESIGN.md) に書いてある。

---

## できること

- 21 媒体（日本語 14／英語 7）から毎朝フィードを取得する
- 同じニュースの重複をまとめ、複数媒体が報じた記事を重要とみなす
- 興味のあるトピックの重みを自分で調整して、選ばれる記事を寄せる
- 5 分／10 分／15 分の番組として台本にする
- ブラウザの音声合成で再生する。コーナー単位で頭出しできる
- その日の記事に出てきた業界用語を解説する。覚えた語は次から出ない
- 過去 30 本を端末に保存する
- 情報源のヘルスチェック。取得できないフィードがすぐ分かる

## 動かす

```bash
cd techcast
npm install
npm run dev
```

http://localhost:5174 を開く。初回は自動でその日の番組を作り始める。

### Claude に台本を書かせる（任意）

APIキーがなくてもテンプレートで番組は作られる。
キーを設定すると、次の 3 つが変わる。

- 英語記事が日本語に直される（未設定だと英語の見出しがそのまま読まれる）
- ニュース同士のつながりが説明される
- 用語解説がその日の文脈に合わせて言い直される

```bash
echo 'ANTHROPIC_API_KEY=sk-ant-...' > .env
npm run dev
```

`.env` はコミットしないこと（リポジトリの `.gitignore` に含まれている）。

### テストと静的検査

```bash
npm test     # 39 ケース。ローカルにフィードサーバーを立てて通しで検証する
npm run lint
npm run build
```

## デプロイ（Vercel）

このディレクトリは独立したアプリなので、**ルートディレクトリを `techcast` に指定した
別プロジェクト**として作るのが一番素直。

1. Vercel で新規プロジェクトを作り、Root Directory に `techcast` を指定する
2. Framework Preset は Vite
3. 環境変数 `ANTHROPIC_API_KEY` を設定する（任意）

`api/` の 3 ファイルがそのままサーバーレス関数になる。
ローカルの `npm run dev` でも同じハンドラが動くように Vite に橋を架けてあるので、
「ローカルでは動くのに本番で動かない」というズレが起きにくい。

## 構成

```
techcast/
├── server/                     ブラウザに依存しない処理。テストはここに集中している
│   ├── sources.js              情報源カタログ（URL・信頼度・扱う領域）
│   ├── rss.js                  RSS 2.0 / RDF / Atom のパーサ（依存ゼロ）
│   ├── match.js                短い英略語の誤爆を防ぐ語マッチ
│   ├── taxonomy.js             16 トピックのタグ推定
│   ├── glossary.js             42 語の用語辞書
│   ├── rank.js                 重複判定・スコアリング・選定
│   ├── script-template.js      オフラインでの台本生成
│   ├── script-claude.js        Claude での台本生成
│   ├── episode-shape.js        エピソードの共通フォーマット
│   ├── pipeline.js             収集から台本までの一本道
│   └── __tests__/              回帰テスト
├── api/                        Vercel サーバーレス関数
│   ├── sources.js              GET  情報源カタログ
│   ├── health.js               POST 情報源のヘルスチェック
│   └── episode.js              POST エピソード生成
└── src/                        React アプリ
    ├── lib/speech.js           音声合成の制御
    ├── lib/store.js            localStorage
    └── views/                  4 タブ
```

### 処理の流れ

```
情報源カタログ
   ↓ 並列取得（1 つ落ちても止めない）
RSS/Atom/RDF パース
   ↓ 重複排除（固有名詞 + 数字 + 文字n-gram の 3 手がかり）
   ↓ スコアリング（鮮度 × 信頼度 × 興味 × 他媒体での言及）
   ↓ 選定（深掘りは 1 媒体 1 本まで／既出は除外）
用語の抽出（覚えた語を除く）
   ↓
台本生成（Claude、失敗したらテンプレート）
   ↓
音声合成で再生
```

## 情報源を足す・直す

`server/sources.js` に 1 件足すだけ。

```js
{
  id: 'example',
  name: '媒体名',
  url: 'https://example.com/feed',
  lang: 'ja',              // 'ja' | 'en'
  tier: 'core',            // 'core' = 既定でON / 'extra' = 設定から追加
  weight: 1.0,             // 1.0 が基準。高いほど選ばれやすい
  tags: ['saas', 'japan'], // taxonomy.js のタグID
  note: 'アプリに表示される一言説明'
}
```

**フィードの URL は移転も停止もする。**
うまく取れなくなったら「情報源」タブのヘルスチェックを実行すると、
どれが落ちているかとその理由（HTTP ステータス、タイムアウト、フィードとして解釈できない）が出る。

## 今のところできないこと

- **画面ロック中の再生**　ブラウザの音声合成は画面を消すと止まる。通勤中にポケットに入れて聞く用途は、
  実音声ファイル化（DESIGN.md のフェーズ2）まで待つ必要がある
- **端末間の同期**　設定と履歴はブラウザの中だけ。設定タブから書き出し／読み込みで移す
- **記事本文の取得**　フィードに含まれる要約までしか読まない。媒体によっては要約が短い
- **英語の日本語化（テンプレート時）**　Claude 経路でのみ翻訳される

---

## 注意していること

- フィードから取った文章は**外部から来たデータ**として扱う。台本生成のとき、
  記事中に指示めいた文言があっても従わないよう明示している
- 手元にあるのは見出しと短い要約だけなので、それを超えた断定をしないよう
  システムプロンプトで縛っている
- 読み上げ原稿に URL や記号を混ぜない（テストで検証している）
